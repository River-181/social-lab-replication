## 4. 매주 갱신 절차

**실행(주 1회, 월요일 기준, 일일 스냅샷은 launchd가 이미 돎):**
1. `yt_search.py`(신규 영상) → `yt_meta.py`(스냅샷) → `yt_livechat.py` → `dc_gall.py`(전용갤 + 관련 갤) → `ingest.py` → `audit.py`. 유튜브 직렬·3초 규칙 유지.
2. 새 사본 `work/lab_YYMMDD.db`를 만들고 `python3 scripts/analysis/rq8_indicators.py work/lab_YYMMDD.db`.
3. 사건표(`events`)에 한 주간의 수사·입법·제도 사건을 사람이 입력(M10). 웹 검색으로 국회 발의·수사 보도를 확인하고 출처 URL을 남긴다.
4. 후속 국면 층화 표본을 코딩해 M8을 갱신(월 1회).
5. 이전 판은 지우지 않고 `findings/YYMMDD_RQ8_시나리오.md`로 새 파일을 만든다(v2, v3…).

**확률 갱신 규칙(간단한 베이지안):**
- 축별로 시나리오 확률 p_i(합 100)를 사전으로 둔다. 새로 관측한 지표 k마다 판별표에서 시나리오별 가능도 비 LR_ik를 정한다. 기준 LR: 해당 시나리오를 뒷받침하는 임계 초과 = 2, 약한 신호 = 1.3, 반대쪽 임계 초과 = 0.5, 무관 = 1.
- 갱신: p_i' ∝ p_i × ∏_k LR_ik^w, 그 뒤 합이 100이 되게 정규화. w는 **같은 원인에서 나온 지표끼리 상관이 있어 이중 계산하는 것을 막는 감쇠**로 0.5를 쓰고(M2·M3·M1은 한 묶음으로 보고 가장 센 하나만 w=1), 한 주에 시나리오 하나가 ±15%p 넘게 움직이면 사람이 근거를 다시 본다.
- 사건 자체가 일어나면(예: 발의 확인, 종결 공식 발표) 해당 시나리오는 1로, 배타적 시나리오는 0으로 확정하고 나머지를 다시 정규화한다.
- 6개월 확률은 30일 확률이 확정되는 대로 그 조건부로 다시 쓴다(예: B3가 30일 안에 오면 B1·B4의 6개월 값이 0).
- 평가: 2026-12-19에 30일, 2027-05-19에 6개월 확률을 실제와 대조한다. 시나리오가 n개일 때 Brier 점수 = Σ(p_i − 결과_i)² 를 축별로 기록한다. 사례가 한 건이라 보정(calibration) 평가는 불가능하고, 점수는 "같은 방식을 쓰는 다음 사건"의 참고로만 남긴다.
- 모든 갱신은 시나리오·지표 판별·이전 값·새 값·이유를 한 줄로 적는다(사후에 근거를 되짚을 수 있게).
